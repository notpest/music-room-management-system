================================================================================
MUSIC ROOM MANAGEMENT SYSTEM - IMPLEMENTATION & DEPLOYMENT STEPS
================================================================================

This document provides a step-by-step roadmap to update dependencies, fix design flaws, optimize performance, configure the Supabase database schema, and deploy to Vercel.

Note: The legacy `parse_gmail.py` script and its background logic are deliberately ignored in this modern web-tier deployment.

--------------------------------------------------------------------------------
PHASE 1: DEPENDENCY CLEANUP & UPDATES
--------------------------------------------------------------------------------
1. Upgrade Core React & Next.js:
   - Run `npm install react@rc react-dom@rc` to update to React 19 (aligning with Next.js 15).
   - Run `npm update next` to ensure the latest patch of Next.js 15.

2. Eliminate UI Dependency Bloat:
   - Identify which UI library is actually preferred (Tailwind is default).
   - Uninstall unused massive libraries to reduce bundle size:
     `npm uninstall @chakra-ui/react @emotion/react @emotion/styled @mui/material @mui/icons-material @nextui-org/react`
   - Consolidate components to use standard Tailwind CSS + Framer Motion. Fix any broken imports in `/components/ui/`.

3. Update ORM & Auth:
   - Run `npm update sequelize pg next-auth bcryptjs`.

--------------------------------------------------------------------------------
PHASE 2: ARCHITECTURAL REFACTORING (FIXING FLAWS)
--------------------------------------------------------------------------------
1. Unify the API Paradigm (Pages to App Router):
   - Move all files from `pages/api/` to `app/api/`.
   - Rewrite them from `export default async function handler(req, res)` to standard App Router Route Handlers:
     `export async function GET(request: Request) { ... }`
     `export async function POST(request: Request) { ... }`
   - Delete the `pages/` directory completely to prevent hybrid routing conflicts.

2. Fix Model Initialization:
   - Open `models/initmodels.ts`.
   - Add imports for ALL missing models to ensure Sequelize registers them at boot:
     `import "./Room";`
     `import "./Slot";`
     `import "./Request";`
     `import "./EntryLog";`
     `import "./SlotConfig";`

3. Fix N+1 Query Bottleneck:
   - Open the newly moved `app/api/requests/route.ts` (formerly `pages/api/requests.ts`).
   - Replace the `Promise.all(requests.map(...))` logic in the GET request.
   - Use Sequelize relational includes instead:
     `const requests = await Request.findAll({ include: [{ model: User, attributes: ['name'] }, { model: Band, attributes: ['name'] }] });`

--------------------------------------------------------------------------------
PHASE 3: OPTIMIZATIONS
--------------------------------------------------------------------------------
1. React Server Components (RSC) Migration:
   - Remove `"use client"` from `app/(root)/page.tsx`, `RoomBooking/page.tsx`, and `EquipmentBooking/page.tsx`.
   - Only place `"use client"` inside leaf components that actually need state (like `RBTable.tsx` or `DashboardTable.tsx`).

2. Database Indexing:
   - Update `models/Slot.ts` and `models/Request.ts` definitions.
   - Add indexes for conflict resolution queries:
     `indexes: [{ fields: ['room_id', 'slot_start', 'slot_end'] }]`

--------------------------------------------------------------------------------
PHASE 4: SUPABASE DATABASE SCHEMA SETUP
--------------------------------------------------------------------------------
1. Initialize Supabase locally:
   - Install Supabase CLI: `npm install -g supabase`
   - Run `supabase init`.

2. Generate SQL Migrations:
   - Instead of relying on `sequelize.sync()`, create a raw SQL schema migration.
   - Run `supabase migration new init_schema`.
   - In the generated `supabase/migrations/..._init_schema.sql` file, write the explicit `CREATE TABLE` commands for `user`, `band`, `user_band`, `room`, `slot`, `request`, `entry_log`, and `slot_config`.
   - Include primary keys (UUIDs), foreign key constraints, and the indexes mentioned in Phase 3.

3. Push to Supabase:
   - Link your project: `supabase link --project-ref <your-supabase-project-id>`
   - Push the schema: `supabase db push`

--------------------------------------------------------------------------------
PHASE 5: VERCEL DEPLOYMENT
--------------------------------------------------------------------------------
1. Prepare Environment Variables:
   - Gather your production values for:
     `DATABASE_URL` (Use the Supabase IPv4 connection pooler URL, typically ending in `?pgbouncer=true`).
     `NEXTAUTH_URL` (Your production Vercel domain, e.g., `https://my-music-room.vercel.app`).
     `NEXTAUTH_SECRET` (Generate a strong random string).

2. Vercel Configuration:
   - Push all refactored code to your GitHub repository.
   - Go to the Vercel Dashboard -> Add New Project -> Import from GitHub.
   - In the deployment settings, paste the Environment Variables gathered above.
   - Ensure the Build Command is `next build` and Install Command is `npm install`.

3. Deploy and Verify:
   - Click "Deploy".
   - Once live, monitor the Vercel Logs for successful database connection initialization.
   - Test the Authentication and Booking flow in the live environment to ensure Edge compatibility.
